# Sweet Studio

Специализированное рабочее пространство кондитера — от первого домашнего заказа до собственной сети кондитерских. Web-first, сначала закрытый пилот на нашем сервере, затем SaaS. Одна подписка бизнеса до 500 ₽/месяц (предложение 499), платит владелец. Сотрудники имеют личные аккаунты. Профили домашний/студия/сеть — настройки, не тарифы. Не обещать безлимит до измерения нагрузки. При истечении подписки — предупреждение, льготный период, чтение и экспорт.

> **Актуальный статус реализации (Web Cloud Pilot):** базовое веб-приложение реализовано на **React 19 + TypeScript + Tailwind CSS + Firebase (Auth & Firestore)** и включает все ключевые разделы (Главная, Работа с канбаном и месячным календарём, Заказы и Заявки, Рецепты с фото/версиями/техкартой, Проф-калькулятор, Кладовая с FEFO и CSV-импортом, Производство, Клиенты, Лояльность, Качество, Продвижение, Финансы с переводами, Аналитика, Команда/зарплата, Настройки с JSON-резервированием и Академия). Подробная матрица готовности и список оставшихся задач этапов 12–16 / Personal Addendum зафиксированы в [`docs/PROGRESS.md`](./PROGRESS.md).

Web-first, сначала закрытый пилот на нашем сервере, затем SaaS. Одна подписка бизнеса до 500 ₽/месяц (предложение 499), платит владелец. Сотрудники имеют личные аккаунты. Профили домашний/студия/сеть — настройки, не тарифы. Не обещать безлимит до измерения нагрузки. При истечении подписки предупреждение, льготный период, чтение и экспорт.

Создать отдельный проект из исходного, ещё не реконструированного Masters. Не менять рабочий Masters. Сначала аудит реального репозитория, лицензий, зависимостей, тестов. Источники: обсуждение, четыре текстовых описания Masters, предыдущий Masters_2_TZ.md. Исходники и сервер не проверены, таблицы расчётов пользователя ещё не получены. HTML — визуальный контракт, не готовый продукт. Конкурентная цель: заменить разрозненные CRM, таблицы, калькуляторы и склад; превосходство проверять на реальных сценариях, не считать доказанным.

Для каждого этапа Codex: изучить код, составить план и ADR, реализовать вертикальный сценарий UI/API/БД, миграции и тесты, записать фактические результаты в docs/PROGRESS.md, обновить REUSE_MAP, SCREEN_MAP, TEST_MATRIX. Малые откатные коммиты. Не скрывать ошибки заглушками. Не менять продовые данные и секреты. P — пилот, B — бета, S — SaaS, X — расширение.

### 3. Архитектура

Flutter Web — кандидат после spike, иначе web-native с переносом алгоритмов через тестовые контракты. PostgreSQL, API с OpenAPI, миграции, приватное файловое хранилище, фоновые задания, HTTPS, staging. Backend выбрать после аудита meaxis-sync. Сервер источник истины, локально кеш/черновики, PWA после проверки. UUID, workspace_id, version, created/updated/by, архив. UTC + timezone бизнеса, date-only отдельно. Деньги целые копейки, количества decimal в базовой единице, детерминированное округление. Транзакции, idempotency keys, optimistic locking, пагинация, ошибки с correlation ID. Не обещать полный offline.

User, Workspace, Membership, Employee (может не иметь аккаунта), Role, Permission, Invitation, Location, Subscription, Preferences, AuditLog. Tenant проверяется сервером для всех записей, файлов, поиска, экспорта, задач и агрегатов. Тест двух предприятий даже в пилоте. Защищённые сессии, CSRF, хеш паролей проверенной библиотекой, rate limit, отзыв сессий, одноразовые приглашения, восстановление доступа. Приватные фото, проверка размера/типа, секреты вне Git, логи без PII и токенов. Backup БД+файлов, проверка восстановления. Правила персональных данных, согласий и фискализации уточнить до запуска.

Роли: владелец (всё, подписка), администратор (без подписки и передачи владения), кондитер (назначенные задачи, разрешённые утверждённые рецепты, выпуск, своя зарплата), продавец (точка, касса, купоны), маркетолог (контент, разрешённые фото/аналитика), кладовщик, бухгалтер. Разрешения view/create/edit/post/reverse/export/approve, scope own/assigned/location/all; отдельно закупочные цены, себестоимость, прибыль, чужая зарплата, контакты. Запрет по умолчанию. Увольнение отзывает доступ, сохраняет историю. Владелец приглашает, не знает пароль сотрудника.

### 5. UX и персонализация

Независимые уровни: модули, права, закреплённые вкладки, поля/виджеты. Скрытие не удаляет данные. Профили домашний (работа, рецепты, кладовая, клиенты, финансы, лояльность), студия (+производство, команда, качество, продвижение), сеть (+точки, кассы, аналитика, опт). Любой модуль можно включить отдельно. Первый вход: лозунг, формат, команда, точки, модули, тема, опциональная изолированная демо-база.

Одна динамическая форма quick/full/template: 2–5 основных полей, подключаемые блоки, порядок, defaults, обязательные системные поля защищены. Скрытие не сбрасывает значения; влияющие на расчёт скрытые поля видны в итогах. Слайдеры веса/партии/скидки/наценки/маржи с точным вводом и настраиваемыми min/max/step, быстрыми чипами. Не обрезать ввод вне диапазона молча. Маржа <100%, вес >0. Searchable picker, inline создание справочника с возвратом в черновик, labels, единицы, ошибки, sticky save/итог. Черновик не проводит операции. Разные команды Создать/Сохранить/Провести/Подтвердить/Сторнировать/Архивировать. Custom fields text/number/money/date/list/bool/phone/file с правами, default, required, фильтром, экспортом.

Глобальный поиск в шапке/Ctrl+K: группы по типам, номер, имя, телефон, теги, комментарии, только разрешённые данные; недавние при пустом запросе. Избранное — звезда карточки, виджет главной, верх picker. Глобальный +: 6 настраиваемых действий (заказ, рецепт, расход, клиент, партия, задача), ниже публикация, закупка, купон, доход, жалоба. Повторить/шаблон в overflow: копировать содержимое, не оплаты, списания, купоны, старые даты/статусы. Autosave черновиков, список в +/главной/разделе, восстановление после закрытия браузера. Undo toast для обратимых действий; проведённые документы только корректировкой. Bell: unread, переход к объекту, категории, тихие часы, получатели, дедупликация. Недавние карточки в поиске и desktop панели. Alt+N, Alt+1/2/3, Esc, Ctrl+Enter только безопасное подтверждение; проверить конфликты браузера.

### 6. Модули и экраны

#### Главная [P]

Период, поступления, расходы, признанная выручка, результат, активные заказы, ближайшие выдачи, просрочки, низкие остатки, истекающие партии, быстрые действия, таймер, черновики, избранное. Настраиваемые виджеты, скрытие сумм, фильтр точки, drill-down. Сотруднику свои задачи/смена, не общие финансы.

#### Работа [P/B]

WorkItem: type, source_type/id, title, assignee, location, start/due, priority, stage, tags, parent, checklist, dependencies, attachments, comments, version. Заказ/выпуск/жалоба/пост остаются самостоятельными сущностями, единая проекция без дублей. Типы: заказ #A45C7A cake; производство #748B64 cooking-pot; продвижение #9275BA megaphone; качество #B67B4E shield-check; поручение #647B9D user-round; закупка #9B8055 basket; финансовая задача #548D80 wallet. Цветная полоса и иконка в углу, статус отдельно. Список/канбан/календарь день-неделя-месяц; без даты очередь. Настраиваемые колонки, mapping специализированных этапов, drag/drop и клавиатурное перемещение. Фильтры тип/исполнитель/точка/клиент/срок/приоритет/тег, сохранённые виды Мои/Сегодня/Просроченные/Производственный план/Контент-план. Перемещение не проводит оплату, списание, выпуск, зарплату или купон. Подзадачи заказа: согласование, закупка, бисквит, крем, сборка, контроль, фото, выдача, пост, отзыв. Домашнему достаточно одной карточки. Повторяющиеся задачи с уникальным occurrence.

#### Заказы и заявки [P]

Заявка: контакт, запрос, источник, бюджет, следующий шаг, конверсия один раз. Заказ: клиент, название/позиции, срок выдачи, вес/количество, цена ручная или из строк, рецепт/версия, фото оформления, пожелания/аллергены, доставка/адрес, исполнитель, точка, скидка/купон, плановый аванс, заметка/теги/приоритет. Снимок рецепта, цены и калькуляции; изменение согласованного заказа ревизией. Статусы заявка/согласование/подтверждён/в работе/готов/выдан/закрыт/отменён. Частичная оплата, депозит, долг, возврат, счёт/метод; не превышать остаток без явной переплаты. Отмена освобождает резерв, не удаляет операции. Карточка обзор/состав/задачи/финансы/файлы/история. Смета/счёт/акт/управленческий чек PDF, не фискальный. Повтор заказа с актуальными ценами. Портфолио из разрешённых фото.

#### Рецепты [P]

Галерея фото, категории торты/капкейки/десерты/кремы/бисквиты/начинки/полуфабрикаты, список/таблица, поиск, теги, избранное. RecipeVersion неизменяемая после утверждения: название, фото, выход масса/шт/порции, форма/диаметр, ингредиенты и вложенные рецепты, gross/net, потери, единицы, технология шагами с фото/временем/температурой, оборудование, хранение/срок годности (задаёт специалист), аллергены, упаковка, труд, ресурсы, автор/версия. Запрет циклов. Черновик/проверка/утверждён/архив; старые версии доступны заказам. Пересчёт веса/порций/партии; линейные, фиксированные, ступенчатые и ручные компоненты; геометрия только при заданных параметрах. Эксперименты отдельными версиями. Доступ конкретным сотрудникам. Создать заказ/партию, пересчитать, дублировать, техкарта PDF. Аллергены наследуются с ручной проверкой, не гарантия отсутствия перекрёстного контакта.

#### Калькулятор [P]

Единое ядро рецепта/заказа/партии/каталога. Базовый ингредиенты+наценка; полный независимые блоки: труд, упаковка, декор, электричество, газ, вода, аренда, амортизация, уборка, хранение, доставка, возвраты, комиссия, эквайринг, реклама, налоги, брак, прочее. Можно отключить любое, сохранить профиль, заложить накладные в наценку. Показывать учтённое/неучтённое, не называть неполный результат чистой прибылью. Тарифы с единицами, точкой, периодом действия; снимки, ручная корректировка с причиной. Не списывать при расчёте.

Формулы-кандидаты: unit cost = стоимость закупки с прямыми расходами / пригодное количество; gross=net/(1-loss), если loss доля gross; строка=gross×unit cost; партия unit cost=фактическая стоимость/пригодный выход. Масштаб target/base. Электричество kW×часы×тариф, газ m³×тариф, вода литры/1000×тариф; фактический счётчик альтернативно. Труд часы×ставка или сдельно. Аренда/накладные по выбранной базе часы/объём/заказы/выручка, нулевая база N/A. Амортизация по сроку/ресурсу. При C без процентных сборов, r доля сборов от цены, m целевая маржа: P=C/(1-r-m), r+m<1. Наценка (P-C)/C, маржа (P-C)/P без сборов; с ними результат P-C-rP. Скидка пересчитывает результат. Break-even фиксированные расходы/положительный вклад единицы; ROI с явной базой. Налоговый режим проверять отдельно. План/факт раздельно, не менять историю при новых тарифах. Аренда как денежный расход и распределённая себестоимость не два расхода. Закупка и расход сырья не удваивают P&L. Таблицы пользователя ожидаются: согласовать формулы и golden tests до окончательной приёмки.

Тест: 3 кг крема стоимость 1800 ₽, 600 ₽/кг, 300 г расход 180 ₽, остаток 2700 г стоимость 1620 ₽. 2 кг рецепта 1240 ₽ → 3 кг 1860 ₽ → наценка 80% =3348 ₽.

### 8. Контракты и тесты приёмки

Уникальность tenant+source для начислений/задач/погашений; повтор ключа с другим payload конфликт. Outbox для уведомлений после commit.

| Рецепты, партии, закупки, заказы, канбан, календарь, финансы, клиенты, качество, локальные купоны, аналитика, обучение | да | да |
| Контент-план и медиатека | да; открытие соцсетей требует сети | да |

| Резервирование | локальный экспорт и восстановление | серверные копии и экспорт |

Personal не означает демоверсию. Сохранять все четыре темы, настройки полей, меню, поиск, избранное, черновики, инструкции и расчётное ядро. Не скрывать существующие данные при изменении лицензии. В Personal один владелец, одна активная рабочая БД; несколько устройств могут иметь независимые копии, но не обещать их автоматическое объединение. Учёт нескольких локальных мест хранения допустим; распределённая работа точек — Cloud. Платёж за Cloud только с аккаунта владельца. Окончательные условия, число активаций, налоги, магазинные комиссии и цена требуют утверждения.

### 11. Архитектура и переиспользование Masters

Основное ТЗ §2–3 и этап 00 сохраняются. Провести spike Flutter Web + Flutter native (Windows, Android, затем iOS/macOS по подтверждённой потребности). Если web-native выбран вместо Flutter Web, обеспечить одинаковые доменные контракты и golden-тесты, не дублировать формулы вручную без тестов. Personal не требует установки PostgreSQL, Docker, Node, внешнего сервера или настройки портов. Предпочтительно Flutter native с SQLite в каталоге данных приложения. Web Cloud остаётся основной пилотной редакцией. PWA не считать полноценным offline-хранилищем: браузер может удалить данные, ограничить объём или фоновые операции.

Разделить domain (чистые расчёты, валидация, переходы состояний), application (use cases), ports (репозитории, файлы, часы, лицензия, уведомления), adapters (SQLite и HTTP API), UI (общие компоненты и адаптивные экраны). Сервер Cloud авторитетно проверяет команды, workspace и права; Personal выполняет те же доменные проверки локально. UUID, копейки, decimal, версии рецептов, партии, аудит, идемпотентность, транзакции и исторические снимки одинаковы. Не копировать старый sync Masters без аудита. Использовать его SQLite, миграции, backup, PDF, payroll и расчётные модули только после проверки. Не считать старые ошибки устранёнными. Сохранить тестовые векторы для обеих редакций.

### 12. Автоматическая установка

Windows: подписанный установщик EXE/MSIX (выбор ADR), установка без ручной настройки окружения, ярлык меню Пуск и опционально рабочего стола, ассоциация резервной копии только по согласованию. Первый запуск создаёт каталог данных, БД, миграции, профиль, демонстрационную базу отдельно. Данные вне каталога программы. Повторная установка не затирает данные. Удаление программы по умолчанию сохраняет данные; полное удаление отдельное подтверждённое действие. Не требовать администратора без необходимости. Проверить чистую Windows и обновление предыдущей версии.

Android: подписанный APK/AAB, официальный канал распространения; локальная БД и медиа в приватном каталоге, экспорт через системный выбор файла. iOS: подписанная сборка и разрешённый канал распространения (App Store/TestFlight для теста); не обещать произвольную установку IPA. Учитывать ограничения платежей магазинов. На телефоне не разворачивать публичный сервер. При необходимости desktop web UI с локальным сервисом — отдельный ADR: loopback only, случайный токен, защита CSRF, автоматический запуск/остановка; не открывать порт в LAN по умолчанию.

Первый запуск: выбор Personal/Cloud, объяснение места хранения, создание бизнеса, тема, модули, импорт или чистая база, настройка копий. Для Personal не требовать облачного аккаунта для повседневной работы; активация может потребовать интернет или импорт подписанного файла. Не загружать данные на сервер без явного согласия.

### 13. Автономная лицензия

Предлагаемый механизм: сервер выдаёт подписанный entitlement с edition, license_id, сроком, версией формата, допустимыми устройствами; приложение проверяет подпись встроенным публичным ключом. Приватный ключ только на сервере. Не хранить секреты оплаты в клиенте. Предусмотреть ручной импорт лицензии для устройства без сети и перенос активации после поломки. Проверка локально при запуске, без ежедневного подключения. Предложение: оплаченный период плюс 14 дней льготы; уточнить с владельцем. Показать дату окончания заранее. При истечении — чтение, экспорт, резервирование, восстановление и продление доступны; не удалять данные и не блокировать доступ к истории. Учитывать перевод часов и откат даты без ложной блокировки; абсолютная защита offline-лицензии невозможна. Не делать скрытую телеметрию обязательной. Сценарии отказа сети, истечения, поддельной подписи, смены устройства и восстановления проверить отдельно.

### 14. Данные, резервирование и обновления

SQLite транзакции, foreign keys, миграции с проверкой целостности и предмиграционной копией. Фотографии хранить локально с относительными идентификаторами, миниатюрами и контролем свободного места. Backup: версионированный контейнер с manifest, schema_version, workspace UUID, БД/логическим экспортом, медиа и контрольными суммами; опциональное шифрование с паролем пользователя. Копирование активной БД только через согласованный snapshot/backup API. Автоматическая ротация (предложение: 7 дневных и 4 недельных), выбор внешней папки, ручной экспорт, напоминание о копии вне устройства. Копия на том же диске не защищает от его поломки. Восстановление сначала во временную БД, проверка ссылок, суммы и медиа, затем атомарная замена с сохранением старой копии. Не перезаписывать данные при ошибке или нехватке места. PIN/биометрия через системные механизмы; не считать PIN шифрованием БД. Обновления подписаны, проверяются при наличии сети, возможна ручная установка; не принуждать к обновлению во время работы. Миграции совместимы с поддерживаемыми версиями экспорта. Проверить восстановление после аварийного завершения и обновления.

### 15. Переход Personal → Cloud

Мастер в Настройки → Данные → Перенести в Cloud. 1) создать/выбрать пустой workspace владельца; 2) сделать локальную копию; 3) предварительная проверка схемы, объёма, валюты, ссылок, дубликатов; 4) загрузка по защищённому каналу с прогрессом и повтором; 5) staging import, проверка количества записей, остатков, финансовых итогов, версий, фото и истории; 6) атомарная публикация; 7) явное переключение источника истины. Повтор импорта с тем же ID не дублирует операции. Локальную базу оставить архивом, не разрешать незаметную параллельную запись. Не импортировать в непустой workspace без отдельного проекта слияния. Cloud → Personal: экспорт доступен владельцу; импорт как новый локальный снимок после проверки совместимости, без чужих паролей, сессий, токенов и платёжных реквизитов. Не обещать двустороннюю синхронизацию. Локальные QR при миграции сверить и перевыпустить при конфликте; не допускать двойного погашения.

### 18. Приёмочные сценарии (дополнение)

- Чистая установка без ручной настройки; запуск и создание базы, ярлык правильный.
- После активации отключить сеть, перезапустить устройство: создать рецепт, партию, заказ, принять оплату, погасить локальный купон, сформировать отчёт и копию.
- Сверить расчёт стоимости и остатки с Cloud на одинаковом наборе операций; повтор команды не удваивает движения.
- Сбой питания/закрытие процесса в середине проведения: нет частично проведённых документов.
- Повторная установка и обновление сохраняют БД, медиа и настройки; неудачная миграция восстанавливается.
- Повреждённая копия, неверный пароль, нехватка диска: исходные данные не меняются.
- Восстановить копию на другом устройстве, проверить фото, историю, финансовые суммы и остатки.
- Истёкшая лицензия, неверная подпись, недоступный сервер, смена часов: данные доступны для чтения и экспорта.
- Personal не открывает сетевой порт и не отправляет данные без согласия; Cloud проверяет изоляцию предприятий.
- Перенос в Cloud с потерей соединения и повтором: нет дублей, итоговые суммы совпадают, старый локальный снимок сохранён.
- Проверить Android/iOS разрешения, системный выбор файлов, крупный шрифт, все темы и работу без сети; iOS только после доступности подписанной сборки.
