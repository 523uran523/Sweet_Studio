# Sweet Studio — ТЗ для Codex

## 1. Цель и правила разработки
**Помогаем развивать ваше дело.** Специализированное рабочее пространство кондитера — от первого домашнего заказа до собственной сети кондитерских. Web-first, сначала закрытый пилот на нашем сервере, затем SaaS. Одна подписка бизнеса до 500 ₽/месяц (предложение 499), платит владелец. Сотрудники имеют личные аккаунты. Профили домашний/студия/сеть — настройки, не тарифы. Не обещать безлимит до измерения нагрузки. При истечении подписки предупреждение, льготный период, чтение и экспорт.

Создать отдельный проект из исходного, ещё не реконструированного Masters. Не менять рабочий Masters. Сначала аудит реального репозитория, лицензий, зависимостей, тестов. Источники: обсуждение, четыре текстовых описания Masters, предыдущий Masters_2_TZ.md. Исходники и сервер не проверены, таблицы расчётов пользователя ещё не получены. HTML — визуальный контракт, не готовый продукт. Конкурентная цель: заменить разрозненные CRM, таблицы, калькуляторы и склад; превосходство проверять на реальных сценариях, не считать доказанным.

Для каждого этапа Codex: изучить код, составить план и ADR, реализовать вертикальный сценарий UI/API/БД, миграции и тесты, записать фактические результаты в docs/PROGRESS.md, обновить REUSE_MAP, SCREEN_MAP, TEST_MATRIX. Малые откатные коммиты. Не скрывать ошибки заглушками. Не менять продовые данные и секреты. P — пилот, B — бета, S — SaaS, X — расширение.

## 3. Архитектура
Flutter Web — кандидат после spike, иначе web-native с переносом алгоритмов через тестовые контракты. PostgreSQL, API с OpenAPI, миграции, приватное файловое хранилище, фоновые задания, HTTPS, staging. Backend выбрать после аудита meaxis-sync. Сервер источник истины, локально кеш/черновики, PWA после проверки. UUID, workspace_id, version, created/updated/by, архив. UTC + timezone бизнеса, date-only отдельно. Деньги целые копейки, количества decimal в базовой единице, детерминированное округление. Транзакции, idempotency keys, optimistic locking, пагинация, ошибки с correlation ID. Не обещать полный offline.

User, Workspace, Membership, Employee (может не иметь аккаунта), Role, Permission, Invitation, Location, Subscription, Preferences, AuditLog. Tenant проверяется сервером для всех записей, файлов, поиска, экспорта, задач и агрегатов. Тест двух предприятий даже в пилоте. Защищённые сессии, CSRF, хеш паролей проверенной библиотекой, rate limit, отзыв сессий, одноразовые приглашения, восстановление доступа. Приватные фото, проверка размера/типа, секреты вне Git, логи без PII и токенов. Backup БД+файлов, проверка восстановления. Правила персональных данных, согласий и фискализации уточнить до запуска.

Роли: владелец (всё, подписка), администратор (без подписки и передачи владения), кондитер (назначенные задачи, разрешённые утверждённые рецепты, выпуск, своя зарплата), продавец (точка, касса, купоны), маркетолог (контент, разрешённые фото/аналитика), кладовщик, бухгалтер. Разрешения view/create/edit/post/reverse/export/approve, scope own/assigned/location/all; отдельно закупочные цены, себестоимость, прибыль, чужая зарплата, контакты. Запрет по умолчанию. Увольнение отзывает доступ, сохраняет историю. Владелец приглашает, не знает пароль сотрудника.

## 5. UX и персонализация
Независимые уровни: модули, права, закреплённые вкладки, поля/виджеты. Скрытие не удаляет данные. Профили домашний (работа, рецепты, кладовая, клиенты, финансы, лояльность), студия (+производство, команда, качество, продвижение), сеть (+точки, кассы, аналитика, опт). Любой модуль можно включить отдельно. Первый вход: лозунг, формат, команда, точки, модули, тема, опциональная изолированная демо-база.

Одна динамическая форма quick/full/template: 2–5 основных полей, подключаемые блоки, порядок, defaults, обязательные системные поля защищены. Скрытие не сбрасывает значения; влияющие на расчёт скрытые поля видны в итогах. Слайдеры веса/партии/скидки/наценки/маржи с точным вводом и настраиваемыми min/max/step, быстрыми чипами. Не обрезать ввод вне диапазона молча. Маржа <100%, вес >0. Searchable picker, inline создание справочника с возвратом в черновик, labels, единицы, ошибки, sticky save/итог. Черновик не проводит операции. Разные команды Создать/Сохранить/Провести/Подтвердить/Сторнировать/Архивировать. Custom fields text/number/money/date/list/bool/phone/file с правами, default, required, фильтром, экспортом.

Глобальный поиск в шапке/Ctrl+K: группы по типам, номер, имя, телефон, теги, комментарии, только разрешённые данные; недавние при пустом запросе. Избранное — звезда карточки, виджет главной, верх picker. Глобальный +: 6 настраиваемых действий (заказ, рецепт, расход, клиент, партия, задача), ниже публикация, закупка, купон, доход, жалоба. Повторить/шаблон в overflow: копировать содержимое, не оплаты, списания, купоны, старые даты/статусы. Autosave черновиков, список в +/главной/разделе, восстановление после закрытия браузера. Undo toast для обратимых действий; проведённые документы только корректировкой. Bell: unread, переход к объекту, категории, тихие часы, получатели, дедупликация. Недавние карточки в поиске и desktop панели. Alt+N, Alt+1/2/3, Esc, Ctrl+Enter только безопасное подтверждение; проверить конфликты браузера.

## 6. Модули и экраны
### Главная [P]
Период, поступления, расходы, признанная выручка, результат, активные заказы, ближайшие выдачи, просрочки, низкие остатки, истекающие партии, быстрые действия, таймер, черновики, избранное. Настраиваемые виджеты, скрытие сумм, фильтр точки, drill-down. Сотруднику свои задачи/смена, не общие финансы.

### Работа [P/B]
WorkItem: type, source_type/id, title, assignee, location, start/due, priority, stage, tags, parent, checklist, dependencies, attachments, comments, version. Заказ/выпуск/жалоба/пост остаются самостоятельными сущностями, единая проекция без дублей. Типы: заказ #A45C7A cake; производство #748B64 cooking-pot; продвижение #9275BA megaphone; качество #B67B4E shield-check; поручение #647B9D user-round; закупка #9B8055 basket; финансовая задача #548D80 wallet. Цветная полоса и иконка в углу, статус отдельно. Список/канбан/календарь день-неделя-месяц; без даты очередь. Настраиваемые колонки, mapping специализированных этапов, drag/drop и клавиатурное перемещение. Фильтры тип/исполнитель/точка/клиент/срок/приоритет/тег, сохранённые виды Мои/Сегодня/Просроченные/Производственный план/Контент-план. Перемещение не проводит оплату, списание, выпуск, зарплату или купон. Подзадачи заказа: согласование, закупка, бисквит, крем, сборка, контроль, фото, выдача, пост, отзыв. Домашнему достаточно одной карточки. Повторяющиеся задачи с уникальным occurrence.

### Заказы и заявки [P]
Заявка: контакт, запрос, источник, бюджет, следующий шаг, конверсия один раз. Заказ: клиент, название/позиции, срок выдачи, вес/количество, цена ручная или из строк, рецепт/версия, фото оформления, пожелания/аллергены, доставка/адрес, исполнитель, точка, скидка/купон, плановый аванс, заметка/теги/приоритет. Снимок рецепта, цены и калькуляции; изменение согласованного заказа ревизией. Статусы заявка/согласование/подтверждён/в работе/готов/выдан/закрыт/отменён. Частичная оплата, депозит, долг, возврат, счёт/метод; не превышать остаток без явной переплаты. Отмена освобождает резерв, не удаляет операции. Карточка обзор/состав/задачи/финансы/файлы/история. Смета/счёт/акт/управленческий чек PDF, не фискальный. Повтор заказа с актуальными ценами. Портфолио из разрешённых фото.

### Рецепты [P]
Галерея фото, категории торты/капкейки/десерты/кремы/бисквиты/начинки/полуфабрикаты, список/таблица, поиск, теги, избранное. RecipeVersion неизменяемая после утверждения: название, фото, выход масса/шт/порции, форма/диаметр, ингредиенты и вложенные рецепты, gross/net, потери, единицы, технология шагами с фото/временем/температурой, оборудование, хранение/срок годности (задаёт специалист), аллергены, упаковка, труд, ресурсы, автор/версия. Запрет циклов. Черновик/проверка/утверждён/архив; старые версии доступны заказам. Пересчёт веса/порций/партии; линейные, фиксированные, ступенчатые и ручные компоненты; геометрия только при заданных параметрах. Эксперименты отдельными версиями. Доступ конкретным сотрудникам. Создать заказ/партию, пересчитать, дублировать, техкарта PDF. Аллергены наследуются с ручной проверкой, не гарантия отсутствия перекрёстного контакта.

### Калькулятор [P]
Единое ядро рецепта/заказа/партии/каталога. Базовый ингредиенты+наценка; полный независимые блоки: труд, упаковка, декор, электричество, газ, вода, аренда, амортизация, уборка, хранение, доставка, возвраты, комиссия, эквайринг, реклама, налоги, брак, прочее. Можно отключить любое, сохранить профиль, заложить накладные в наценку. Показывать учтённое/неучтённое, не называть неполный результат чистой прибылью. Тарифы с единицами, точкой, периодом действия; снимки, ручная корректировка с причиной. Не списывать при расчёте.

Формулы-кандидаты: unit cost = стоимость закупки с прямыми расходами / пригодное количество; gross=net/(1-loss), если loss доля gross; строка=gross×unit cost; партия unit cost=фактическая стоимость/пригодный выход. Масштаб target/base. Электричество kW×часы×тариф, газ m³×тариф, вода литры/1000×тариф; фактический счётчик альтернативно. Труд часы×ставка или сдельно. Аренда/накладные по выбранной базе часы/объём/заказы/выручка, нулевая база N/A. Амортизация по сроку/ресурсу. При C без процентных сборов, r доля сборов от цены, m целевая маржа: P=C/(1-r-m), r+m<1. Наценка (P-C)/C, маржа (P-C)/P без сборов; с ними результат P-C-rP. Скидка пересчитывает результат. Break-even фиксированные расходы/положительный вклад единицы; ROI с явной базой. Налоговый режим проверять отдельно. План/факт раздельно, не менять историю при новых тарифах. Аренда как денежный расход и распределённая себестоимость не два расхода. Закупка и расход сырья не удваивают P&L. Таблицы пользователя ожидаются: согласовать формулы и golden tests до окончательной приёмки.

Тест: 3 кг крема стоимость 1800 ₽, 600 ₽/кг, 300 г расход 180 ₽, остаток 2700 г стоимость 1620 ₽. 2 кг рецепта 1240 ₽ → 3 кг 1860 ₽ → наценка 80% =3348 ₽.

### Кладовая [P]
Сырьё/полуфабрикат/готовое изделие/упаковка/расходник/услуга без остатков/инструмент X. Название, категория, единица, SKU, поставщик, цена, min, location, срок, фото, аллерген, track stock. Конверсии совместимых размерностей, плотность явно. Lot: источник, дата, expiry, исходное/доступное/резерв/остаток, unit cost, status, recipe version, фактический выход. FEFO пригодных партий, ручной выбор с причиной, фактическая стоимость партии. Движения append-only: приход, расход, перемещение, резерв/освобождение, возврат, списание, инвентаризация, выпуск. Черновик→проведение→коррекция, атомарность, без отрицательного доступного остатка. Партии показывают остаток, стоимость, цену за г/кг, срок, точку, историю. Карточка сырья: партии/движения/поставщики/рецепты. Закупки из потребности минус доступный остаток, поставщик, позиции, доставка, план/факт, частичная приёмка, связь с обязательством/расходом. Возврат сохраняет происхождение и стоимость. Импорт XLSX preview/mapping/dry run/ошибки, экспорт. Min/expiry уведомления.

### Производство [P/B]
План заказа или витрины, рецепт/версия, плановый и фактический выход, кухня, сроки, исполнитель, оборудование, чек-лист, потребность/резерв, этапы, контроль. WorkItem. Запуск/пауза отдельно от выпуска. Проведение одной транзакцией списывает выбранные партии, фиксирует труд/ресурсы, создаёт партию и lineage. Брак/потери с причиной. Продажа готового изделия списывает его, не сырьё повторно. Без склада ручной факт затрат. Коррекция выпуска с проверкой использованных потомков. Загрузка кухни/сотрудников, конфликты, смены, производственный календарь, оптовые партии. Трассировка сырья до заказов.

### Клиенты и лояльность [P/B]
Имя/компания, телефон/email/мессенджер, адреса, источник, теги, согласия, предпочтения вкуса/сладости/декора, аллергены со слов клиента, даты событий, персональные версии рецептов, история заказов/оплат/долгов/жалоб/купонов. Дубли и слияние с аудитом. Напоминания при согласии. Депозит/сертификат отдельные обязательства. Одноразовый персональный QR: процент/сумма, клиент, срок, min сумма, товары/точки, совместимость, статус. QR случайный токен без PII, серверная проверка, камера HTTPS + ручной код, preview скидки, атомарное погашение с продажей, защита от двух касс. Отмена по политике с аудитом. Печать/скачивание/ручная отправка. Баллы и уровни X.

### Качество [P/B]
Жалоба: клиент/заказ/партия/версия, дата, канал, категория вкус/оформление/доставка/упаковка/прочее, описание, фото, серьёзность, ответственный, срок, статус, решение, компенсация связанной операцией. ### Финансы [P/B]

Аванс и признанная выручка различны, политика признания при выдаче/продаже, P&L себестоимость проданного и расходы периода без дублей, cashflow отдельно. Дебиторка/кредиторка, частичное погашение. Регулярные аренда/коммунальные/подписки: период, дата, сумма, категория, счёт, напоминание/черновик. Бюджет план/факт, налоговые профили и резерв с актуальными ставками после проверки. Закрытие периода, корректировки. Касса: открытие, начальная наличность, продажи/возвраты/внесение/выемка, ожидаемый/факт, расхождение, закрытие. Управленческий учёт не ККТ; интеграция отдельно. ## 8. Контракты и тесты приёмки
API ресурсы: /workspaces, /members, /locations, /clients, /leads, /orders, /work-items, /recipes/versions, /items, /lots, /stock-documents, /production-runs, /accounts, /transactions, /coupons, /complaints, /channels, /posts, /employees, /payroll-periods, /reports, /preferences. Команды post/reverse/approve/redeem/close/reopen отдельны от PATCH. Снимок содержит версию расчёта и исходные данные. Ошибки 401/403/404/409/422 без утечки чужих данных. Уникальность tenant+source для начислений/задач/погашений; повтор ключа с другим payload конфликт. Outbox для уведомлений после commit.

- T01: два предприятия; чужие ID, файлы, поиск, экспорт, агрегаты и фоновые задания недоступны.
- T02: сотрудник видит назначенный рецепт, но не себестоимость/чужую зарплату; отзыв доступа действует на активную сессию.
- T03: четыре темы, 360/768/1440 px, zoom 200%, клавиатура, контраст, reduced motion.
- T04: отключение модуля/поля не удаляет данные; обязательные поля не обходятся; draft восстанавливается после reload.
- T05: 3 кг крема за 1800, расход 300 г за 180, остаток 2700 г за 1620; новая закупка не меняет историю.
- T06: конкурентный расход одной партии, повтор запроса, потеря ответа — нет отрицательного остатка и дубля.
- T07: FEFO исключает карантин/истёкшие партии; перемещение и возврат сохраняют стоимость.
- T08: вложенный рецепт без циклов; утверждённая версия неизменна; старый заказ не меняется.
- T09: расчёт веса, тарифов, потерь, аренды, комиссии, маржи, скидки, нулевых знаменателей; точный ввод за пределом слайдера.
- T10: заказ и связанные задачи видны во всех трёх представлениях; drag не проводит документы; конфликт версий не теряет данные.
- T11: аванс/остаток/возврат/перевод, повтор оплаты, закрытие периода; P&L не удваивает закупку и расход сырья.
- T12: выпуск атомарен, фактический выход и стоимость, продажа готовой партии без повторного списания сырья.
- T13: QR два одновременных погашения — только одно; неверный клиент/точка/срок отклоняются.
- T14: жалоба связана с заказом/версией/партией; карантин блокирует продажу, корректировка рецепта новой версией.
- T15: публикация появляется в общем календаре; ссылка открывается, статус опубликовано только по факту; бюджет не дублирует расход.
- T16: payroll preview=close, повтор close, missing conditions review, reopen с причиной, исторический PDF неизменен.
- T17: касса ожидаемый/факт, возврат, перемещение двух точек, права продавца.
- T18: импорт dry run, дубли, неверные единицы, частичный сбой, экспорт и восстановление backup.
- T19: subscription webhook повтор/неверная подпись, льготный период, чтение/экспорт; только владелец платит.
- T20: пилотные сценарии с реальным кондитером; фиксировать время и ошибки, не считать цели измеренными.

Цели UX: клиент/расход 5–10 с, заказ 10–20 с, повтор 5–10 с, пересчёт 3–5 с, QR 3–5 с, рецепт/остаток 2–3 действия, таймер 1–2, партия 10–20 с. Измерить на пилоте. Проверять Chrome/Firefox/Safari/Edge и мобильные браузеры, сеть с задержкой, reload, две вкладки, камера HTTPS, доступность. Производительность и RPO/RTO установить после аудита сервера, измерить p95 и восстановление. Наблюдаемость: ошибки API, latency, очередь, место диска, backup age, расход хранения на tenant, без PII.

## 9. Открытые решения и выпуск
Нужны исходный репозиторий Masters, конфигурация сервера (без секретов в чате), таблицы калькуляций, реальные сценарии пилота, политика признания выручки/распределения затрат, юридические требования к данным/кассам/налогам/платежам, лимиты подписки. Не считать предложенные формулы и роли окончательно подтверждёнными. До production: резервная копия, миграция на staging, smoke tests, rollback plan, HTTPS, закрытая регистрация, владелец создан безопасным способом, инструкция, мониторинг, согласие на использование реальных данных. После пилота — приоритизация по наблюдаемым проблемам, не добавлять всё сразу.
